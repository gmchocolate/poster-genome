# Reference-First 创作：先看真图，再动手设计

## 默认流程

普通创作任务默认从**用户私有参考图库**中检索 1–3 张真实图像，而不是只读取设计基因 JSON：

1. 识别用户本次上传的内容照片，列出必须保留的主体、数量、面容、服饰、产品、logo、原文和画幅。
2. 在本地 Taste Library 查询相关参考图，读取用户记录的 **liked_for** 和 **avoid_copying**；必要时用视觉能力查看候选图片的具体布局。可结合公用基因规则选择一个最合适的设计方向。
3. 如果图库为空或没有合适参考，只问用户是否添加一张喜欢的海报（用户也可以明确允许无参考创作）。**不能假装有参考图**。
4. 生成包含“内容图”和“风格参考图”的不同角色的输入清单。CLI 不会自动调用云端模型，也不会把图片以二进制数据提交给模型。
5. **实际把参考图片传入有图像输入能力的工具**：打开或附加文件的图像内容。只把文件路径写进提示词不算完成。若宿主只能发送文字，必须解释能力限制。
6. 生成原创视觉构图，优先学习视觉节奏、色彩、字体对比和边缘设计；**不照搬原海报的完整独特组合、原品牌标识或文案**。
7. 用用户源图校验所有人、宠物和产品都出现，并且主体可识别。对于高精度人脸、商标、物品以及精确中文、日期，优先使用可控编辑或平面合成，不依赖模型幻想补齐。
8. 交付最终作品和简短设计依据；允许用户反馈哪些设计细节好/不好，并在用户批准后把偏好更新到本地库。

## 生成输入清单

命令应在已安装 Skill 目录执行。仅生成 JSON 清单，**不是生图命令**：

~~~bash
python scripts/taste_library.py prepare \
  --source "/path/to/blue-hat.jpg" \
  --source "/path/to/pink-hat.jpg" \
  --genome playful-sky-editorial \
  --tag baby --top 2 \
  --headline "双宝出行日记" \
  --out "/private/workdir/create-inputs.json"
~~~

结果明确分开：

~~~text
content_images          → 用户真实照片；负责人物/产品/数量/保真
style_reference_images  → 喜欢的海报；负责排版、字体、色彩与情绪
genome_id               → 规则与禁忌
constraints             → 必须保持的要求
attachment_required     → 必须把图像作为真正的多模态输入
warnings                → 无参考图等未满足条件
~~~

**严禁把参考海报当成用户照片，更不能只给图片文字描述后声称“已使用视觉参考”。**

## 三种工具能力对应三种执行路径

| 宿主支持什么 | 正确做法 | 不能声称什么 |
| --- | --- | --- |
| 多图视觉生成 / 编辑 | 实际附加内容照片和 1–3 张风格参考图，清楚区分角色；再检查结果 | 不能保证模型严格遵守所有排版或人脸细节 |
| 只支持一张图的图像生成 + 本地排版 | 让图像工具实际查看风格参考、生成适合的背景/图形；由可靠的合成工具放置原始照片和准确文字 | 不能称作直接的多图联合条件生成 |
| 只有文字或没有文件权限 | 输出方案，解释哪些视觉参考图未能交给生图工具；请求授权传图或换支持多图的宿主 | 不能宣称生成已被用户的参考图条件化 |

**注意：** 选择到本地文件的绝对路径只是前提，不代表宿主图像工具能够读取它。必须以实际支持的图片加载/附加接口完成传递，并核查工具是否接受了图像。

## 参考图应该影响什么？

用户本次上传的两张宝宝照片与其喜欢的天空摄影海报是一个典型案例：

- **可以借鉴：** 米白纸面、短粗体标题与手写字重叠的节奏、松弛的虚线、照片外的细小标签、视觉重音和不对称关系。
- **必须保留：** 两个宝宝各自的脸、衣物、推车、画面中真实存在的信息，以及两人都出现这一硬约束。
- **需要适配：** 原风格是单图，用户提供的是双人双图；可以考虑一张主图加一张局部插页、上下错列或不对称的双图交错，而不是盲目复制单图位置，也不是机械变成左右等宽相册。
- **不可以抄：** 原设计师的完整图文排布、符号标志、已存在的独特标题文案和未经核实的相机参数。

这种改变才是“学习风格”而不是“换皮”。

## 设计图像与保真图层分离

当用户要求人脸、宠物或商品精确保真时：

- 先保留源图片的像素，并用受控裁切/遮罩/分层合成。
- 风格参考主要用于生成或建议背景、排版装饰、留白和美术风格。
- 精确文本、品牌和必要信息最终用确定性排版工具处理。
- 不把“生成了两个看起来相似的宝宝”当作“保留了用户的两个真实宝宝”。

只有像素级检查、人工检查或其他确实执行的验证才能被报告为“已核对”；尚未验证的地方要说明。

## 创作审美不等于版权复制

参考图片保留在个人设备只是为用户分析与个人创作提供视觉语境。不得因为图像可用就直接复刻他人的独特整体表达，尤其是已有标志、文字内容、独特插画组合。要保留设计方法，并让主体、叙事与版式重新组合。

参考图库仅是用户私有资产。调用外部图像服务时须根据用户许可和该服务政策决定是否上传；本地保存不等于授权云端共享。
