# 怎样知道 Poster Genome 真的有用？

不同的“通过”是不同的事。技能结构通过检查，不代表 AI 看对了海报；一张作品好看，也不代表能在所有用户、图片和客户端上稳定复现。

## 目前提供的四级验证

| 验证层次 | 需要做什么 | 当前状态 |
| --- | --- | --- |
| **文件与格式** | 检查 Skill 入口、JSON 格式、文件链接、代码语法 | 仓库提供自动化测试，具体结果看 Actions |
| **安装打包** | 用 Skills CLI 发现技能，并确认安装目录含参考文件、基因、脚本 | 仓库提供 CI 检查；不等于所有客户端已实测 |
| **Agent 行为** | 同样的参考图和简报，检查能否区分观察与推断、选型是否合理、有没有擅改文案 | **尚未形成跨模型正式结果** |
| **真人观看和创作效果** | 让目标读者识别主题、回忆信息、评价可读性和偏好；比较设计师作品或对照方案 | **尚无可宣称的系统实验结果** |

## 静态测试不做什么

`python -m unittest discover -s tests -v` 与 `validate_library.py` 只能检查仓库结构和一些可执行规则。它们不会调用任何图像模型，不能识别真实人物是否失真，也不能验证设计好不好看。

匹配算法的 100 分说明**给出的主体、用途、情绪、比例等条件全部命中既定列表**，不是创作质量的科学分数。质量审阅表中的“满分 100”同样只供交流，不能直接当成真实用户数据。

## 设计行为测试怎么做

为不同输入预先建立测试集，不要只留成功样例：

1. **参考海报学习：** 人像、产品、图形文字等，每类至少准备高/低清晰度和不同文字密度的素材。
2. **设计推理：** 让独立评审者核查“观察”是否可见，“推断”是否被误说为事实。
3. **原创适配：** 将同一基因用于不同主体、比例和文案长度，检查是否只是生硬套版。
4. **保真与错误：** 故意加入长中文标题、复杂数字、双人合照、商标或遮挡，检查文字与主体是否被错误处理。
5. **不该改：** 输入已经很清楚的成品，检查 Agent 是否能够建议保留原样。
6. **限制行为：** 不给图像工具时，Agent 是否坦白未实际生成图片。

记录模型、版本、提示词、所用工具、输入条件、原始输出、评审人和失败案例。不要仅保存最终挑选的好看图片。

## 有真实读者时怎么比较

可以比较三种版本：**A 原始方案，B 普通生成方案，C 使用 Poster Genome 的方案**。在同一用途下控制文案、尺寸、主体来源与约束，并随机向不同读者展示一个版本，减少互相影响。

预先设计问题，例如：“第一眼看到的主体是什么？”“海报的时间地点是什么？”“你会不会误读价格条件？”同时收集可读性、主观喜欢程度、观看时间与事实记忆。最好由不知道版本来源的独立人员评审，并公开记录负面结果。

“更喜欢”不等于“信息理解更准确”；“浏览更快”也不等于“记得更牢”。只有样本与测量支持时才可以下结论，并写明适用人群和误差范围。

## 未来改进顺序

先完善失败案例和多图测试，再建立跨模型重复测试，最后根据真实用户数据调整设计基因和评审规范。不要在还没有这些证据时写“理解提升 50%”“自动超过专业设计师”等营销承诺。


## v0.3：Reference-First 功能的验证边界

静态测试现在还会检查：本地参考图实际写入、JPEG/PNG 去除元数据、私有索引去重、样式标签筛选、生成输入清单区分 content_images/style_reference_images，以及无参考时发出明确警告。

但这些测试**不等于**真实模型已经读取了参考图片，也不等于创作后的审美质量改善。真实端到端验收必须记录：

1. Agent 使用了哪一个实际本地参考图 ID（不可把私人原图公开在 CI 中）；
2. 生成工具调用是否确实接收内容照片和参考图的图像二进制/附件；
3. 输出是否保留所有指定主体及准确文字，有无编造摄影参数；
4. 人工评审是否认可参考图的版式、色彩、字形关系和节奏被转化，而非复制完整独特表达。

建议对同一份素材比较“无参考仅规则”“参考图进入生成但不强制保真”“真实参考图加受控排版保真”的结果。报告评分标准、测试提示词、负面案例以及使用模型和工具版本。主观审美尚未进行可靠对照试验，不应宣称自动提升了多少百分比。
