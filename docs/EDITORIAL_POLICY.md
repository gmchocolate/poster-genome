# 为什么这样写：Poster Genome 的中文可理解性原则

本次文档组织借鉴开源项目 [comprehensibility-zh](https://github.com/gmchocolate/comprehensibility-zh) 的 **deep 模式**：先确定读者要完成什么，再按问题和依赖关系重排内容，同时保护事实、条件、状态和命令。这里总结的是**我们对 Poster Genome 文档的使用方式**，不声称已通过真人理解实验。

## 先确定谁在看、他想做什么

| 读者 | 他最先关心的问题 | 推荐入口 |
| --- | --- | --- |
| 第一次听说项目的人 | 它做什么？怎么安装？ | `README.zh-CN.md` |
| 想让 AI 设计海报的用户 | 我上传图片后会发生什么？ | README 的例子与 `SKILL.md` |
| 让 Agent 正式执行的人 | 哪些信息不能改？没有图像工具怎么办？ | `skills/poster-genome/SKILL.md` |
| 贡献设计基因的人 | 怎样新增、什么时候不适用、如何验证？ | `CONTRIBUTING.md` |
| 维护代码的人 | 什么格式权威、哪项测试验证什么？ | `schemas/`、`tests/` 与 `docs/EVALUATION.md` |

深度改写不等于全部变成短句，而是让每一节**解决读者当下产生的疑问**。

## 六个重点检查

1. **词语：** “设计基因”首次出现就解释为“可复用的设计规则”；“匹配分数”明确是筛选启发式，不是审美质量分。
2. **句子：** 尽量说清谁做什么。比如“自动适配视觉框架”改成“先检查照片主体，再选布局并调整文字区”。
3. **关系：** 图片观察、设计推断、无法确认分别标明；不要把相关性或设计猜测写成已证明因果。
4. **信息量：** 先给用户命令和示例；JSON 字段、开发测试放在后面和专门文件。
5. **阅读顺序：** “它是什么 → 怎么装 → 怎么学 → 怎么做 → 为什么要积累基因 → 有什么限制 → 如何贡献”。
6. **精度：** 原样保护 `npx skills add gmchocolate/poster-genome`、路径、参数、Schema 字段、权重、用户文案和授权边界。

优先级：**P0 不改坏事实和功能 → P1 消除误解 → P2 表达顺畅 → P3 简洁与文风。** 原文已经清楚时可以不动。图片设计中的诗意文案不必机械改成说明书。

## 两个典型误读

**误读 1：装上 Skill 就能生成图片。**

不准确：“安装后即可自动生成所有风格海报。”

准确：“安装后 Agent 会获得一套海报分析与创作流程；实际图片生成需要客户端具备图像工具。”

**误读 2：分数越高越好看。**

不准确：“匹配分数 100 分，说明最终海报质量最好。”

准确：“100 分表示已填写的几个条件都在该基因的适用列表中；还需要结合照片、文案和实际输出判断。”

这些修改不是风格润色，而是在保护用户对能力和结果的理解。

## 跨文件保真检查

- **权威位置：** 执行约束看 Skill；字段看 Schema；安装命令看安装指南；评估定义看评估文档。README 只做必要摘要。
- **双向核对：** 旧文档里的事实、条件、版本、能力边界是否都还在？新文档有没有加入无法证实的新功能？
- **链接与命令：** 改目录后逐条检查相对链接；运行测试和实际安装检查。
- **不确定性：** “尚未测试”不等于“测试失败”，格式检查通过不等于模型和真人都通过。
- **评价方法：** 本次使用的是编辑判断与静态检查。阅读更顺畅的实际效果需要目标读者测试，见 [评估方法](EVALUATION.md)。
